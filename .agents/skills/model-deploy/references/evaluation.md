# 按需评价与实验记录

## 现有入口与结果文件

现有 MTK 与 RDK 入口包含以下评价步骤.按本次任务选择评价范围,适配阶段可只做所需步骤,例如导出、编译或加载排查.

主机 compile.sh 包含固定子集浮点精度并上传必要参考.板端 compile.sh 运行相同子集,记录任务精度、损失和小样本 CosSim/RMSE/NRMSE 至 results/summary_test.json,同时生成示例.

主机 evaluate.sh 使用已有模型完成约定范围浮点精度并上传必要输入及参考.板端 evaluate.sh 运行同范围精度、性能与峰值 RSS,保存 results/summary.json.小样本评价标 subset,完整基准按相应协议记录.两份报告互不覆盖.

主机过程数据在本地日期临时目录;板端必要参考在 build/reference/,当前预测和评分数据在 build/work/,每次运行前覆盖.单文件 DLA/HBM 沿用本平台布局,多文件包在 models/,代码在 board/.正式原始模型仍存 NAS original/,转换中间产物在 build/,不向 NAS 保存评价张量或数据库.

两端公共精度接口由 tools.evaluation.accuracy_result 构造,明确模型、来源、范围、样本数及单位、样本集合标识和指标方向.公共汇总严格读取此接口,不按旧字段猜测报告类型.全量评价不收集输出张量或重复计算小样本数值误差.

## 精度与真实性

终端只显示阶段、必要进度和最终结果,不逐样本重复打印完整命令及成功信息.过程文件只保留覆盖校验、评分或排错必需的预测、张量和解析日志,同一数据尽量汇总保存,不因为位于临时目录就额外复制.兼容现有运行器必需的文件格式,不为减少文件破坏评分与失败定位.

- LLM 的少量生成示例额外显示输入文本及实际聊天模板、Prefill 提示和实时生成文本,结束时显示停止原因与示例位置.此要求不扩展到 MMLU/WikiText2 逐题评分或非 LLM 模型;独立预热和性能测量关闭文本流式打印,仅在测量外提示阶段.
- 编译阶段比较同子集任务精度及少量输出数值误差,不把子集结果当作全量成绩.
- 正式精度核对完整覆盖、预后处理、标签映射、人体框、文本规范化和评分协议,据实说明校准与评价集重叠.
- 参考与目标板 NPU/BPU 必须属于同一模型版本和协议,同为 full 不足以证明可比.无匹配参考时记录绝对精度,差值留空并说明原因.
- AP/AR/准确率/WER 的变化用原始值算百分点,PPL 用绝对差或相对变化,不称百分点.
- 缺数据、上下文不足或程序错误时停止,不能截题、丢样本、修改阈值或自动重编译后继续宣称原模型成绩.
- 复用现有 LLM 基准时,使用固定 1000 题、57 学科、seed=17 的分层 MMLU 子集和完整 WikiText2 test.该基准中的 full 表示完整执行约定范围,MMLU 仍标为千题子集.核对部署图、配置和输入契约对应同一次转换.具体适配差异及历史记录保存在对应模型文档.
- 区分官方权重存储 dtype 与本地参考参数/计算精度及设备,本地复现不能标成官方公布分数.MMLU 保留约定的提示词及选项评分,验证完整提示词后的选项 Token 延续,不因模型用于聊天就自动套用 Chat Template.主机与板端共用固定题目清单,变更抽样或协议后不直接比较旧基线.
- 量化精度按已确认的部署配置执行.精度退化先区分原框架、SDK 浮点转换、同图量化软件执行和 NPU/BPU 的误差.按授权范围用小样本定位,结合实际用途和同版本对照解释差异.

## 性能与内存

- 只在评价阶段执行必要预热并记录有效计数、样本单位和计时范围.分别给出纯 NPU 与可用端到端数据,未测分项留空并说明,不使用主机数据替代.
- LLM 区分 Prefill/Decode,记录上下文、输入/生成 Token 数与速度协议.自由生成样例速度不能标为固定 128 Token 基准.
- MTK 与 S100 的推理、评分和性能统计统一使用 Python,RSS 使用实际 Python 推理进程高水位并注明采集范围.不能把系统可用内存下降当成 RSS,也不能把 RSS 当成全部驱动/NPU 内存.从 C++ 或原生 CLI 迁移后重新实测,不沿用旧实现的性能和 RSS 数值.
- 不按指标分别保存对外 JSON/CSV/Markdown,统一在一个 summary.json 内记录精度、性能、RSS、范围和缺失项.

## summary.json 最低内容

模型与量化版本、运行编号、实际平台环境、评价协议和覆盖数量、参考与板端精度及变化、性能统计、进程峰值 RSS 及其范围.单任务可使用清晰的平铺指标,多任务 LLM 可使用 accuracy 子项,不重复存储同一数值.

本次结果核对完成后保存报告,重复评价按现有结果文件约定更新.失败、部分完成或未评价须明确标识,按版本区分历史数据和本次实测.在相关 README、模型总览或索引链接实际结果,记录做过的实验及其范围.

## 跨平台 LLM 统一指标与协议

部署优先采用各平台官方 SDK,评价指标与协议保持一致,不要求厂商使用相同量化算法.Qwen 等模型使用自身同版本原始权重的浮点基线,不能用 MTK 其他模型的分数计算损失.区分官方原始权重 dtype、浮点参考参数/计算 dtype 和实际设备.

| 项目 | 统一口径 |
| --- | --- |
| MMLU | 0-shot、固定题目清单、seed=17;正式 1000 题覆盖 57 学科,常规快速子集 100 题也保留学科覆盖.记录正确数、Accuracy、浮点下降百分点与预测一致率.验证完整 Prompt 后空格加 A/B/C/D 的 Token 延续,不自动套聊天模板 |
| WikiText2 | 真实 TEST Token 流划分为 128 Token 块,每块重置上下文,计分后 127 Token;按总 NLL/有效 Token 数计算 PPL.记录尾部处理和覆盖.常规快速子集 16 块,正式使用完整 test 的全部完整块;报告浮点/BPU PPL、绝对差与相对增幅 |
| 数值误差 | 相同输入、有效位置与对应输出;LLM 限首个 Prefill logits.报告 CosSim、RMSE、NRMSE=100*RMSE/RMS(reference),分母为零明确缺失.不比较不同模型 logits |
| 性能 | 独立预热后使用 128 个真实输入 Token、最多生成 128 Token;记录实际生成数、EOS/上限停止原因、预热及有效测量次数.TTFT、Prefill/Decode token/s、端到端耗时注明边界,提前 EOS 不称完成 128 Token 基准 |
| 内存 | 实际 Python 推理进程峰值 RSS,注明生成/精度评价等采集范围;驱动/BPU 专用内存单列,未测留空 |
| 体积 | 编译模型、外置 embedding 等必要辅助权重、原始权重及部署总大小;不只统计单个 DLA/HBM |

Prefill 编译分块可随官方 SDK 不同,例如实际输入 128 Token 在 256 分块图执行,必须同时记录有效长度和补齐长度.不同计时边界不能直接比较.厂商公开 benchmark、SDK 默认 2048 Token PPL 等不同协议成绩仅供诊断,不能混入本仓库报告.

结果汇总沿用 tools.evaluation 的明确接口.新增平台适配在后端处理 I/O、缓存和执行,不要在公共计分代码中按模型名称或字段是否存在猜测.已有 MTK 特定张量导出不能不加核对地直接用于 HBM.
