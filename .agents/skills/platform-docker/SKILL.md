# 全平台 Docker 环境

## 交付边界

模型交付要求见 [model-deploy skill](../model-deploy/SKILL.md),环境规则仅在本 skill 维护.先读取目标平台 docker/ 下的 Dockerfile、依赖声明、构建/创建/进入入口和本地配置.核对当前镜像 ID、容器挂载、普通用户及 Git 状态.不把不同平台的 Python/SDK 版本强制统一.

## 修改与构建

1. 从全部已接入模型的导出、转换、评分和示例代码核对依赖,不能只补当前报错的模块.新增依赖同时更新版本声明和验收,明确来源及兼容约束.
2. 唯一正式 Dockerfile 从声明的基础镜像构建.安装过程必须解析依赖并检查冲突;离线 wheel 只作为缓存来源,不能用 --no-deps 掩盖缺项.不依赖旧容器可写层、用户 HOME 或 SDK 挂载目录中的未声明软件.
3. 保持模型和数据集外部挂载,不打入镜像;密钥和连接信息只在本地配置.构建记录及最终包版本保留在镜像中.变更依赖或验收后必须使镜像重建,创建入口拒绝过时配方.
4. 构建候选镜像,在不挂载模型数据的全新容器中验证依赖和轻量功能.再以实际普通用户及正式挂载验证使用条件.任一阶段失败,修复正式配方后重建,不手工修好候选容器充当通过.

## 必需验收

- 每个已接入模型都有导出、转换、评分和示例的必要模块导入检查,包括延迟导入的模块.用小型合成数据调用评分接口,不只检查 pip 包名.
- SDK 动态库和编译器可用;CPU 构建检查与真实 GPU 检查分开,未测 GPU 不宣称通过.推理硬件仍在对应开发板验收.
- 模型/数据集/SDK 挂载符合本地配置,工作目录及回传路径正确;实际普通用户可写过程目录且宿主机文件属主正确.
- 用全新容器执行,不加载模型权重、不重新编译模型、不运行全量数据集.确需额外耗时任务仍遵守用户授权.

## 替换与收尾

先报告验收证据和限制,再按授权替换旧容器.切换前检查活动任务,保存必要未挂载文件,不要归档整份含历史模型的容器或保留一堆镜像.按明确清单删除本项目旧容器、旧标签及无人使用的旧镜像,禁止全局 prune 或删除其他业务、其他平台环境.保存的诊断记录放日期临时目录,不复制进仓库.

说明实际镜像、各阶段验收、清理范围和未完成项.任何失败都不能用“基本可用”代替验收通过.
