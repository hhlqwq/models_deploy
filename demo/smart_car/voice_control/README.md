# Whisper + Qwen3-0.6B 语音输入、文本输出 Demo 开发计划

状态: **计划阶段,尚未实现、编译或进行板端验证**.本轮仅交付本文档,开发须在计划确认后开始.

## 在小车工程中的位置

本目录是小车应用的独立语音子 Demo,公共构建、依赖管理与平台切换遵循 [Demo 总体工程计划](../README.md).独立运行完成手机语音到文本问答,最终由 `robot_demo` 复用同一实现,不复制业务代码.

除手机与终端展示外,增加独立 ROS 2 适配层,发布转录、回答和请求状态,便于整体集成.首版仍不从自然语言生成底盘指令;结构化任务及任务反馈在整体集成阶段定义.ROS 消息不进入核心接口,请求编号用于关联一次录音、转录、回答及终态.

## 目标与范围

在 MT8189 / Genio 720 上提供 C++ 应用工程: 手机 App 录音,通过 Wi-Fi 或蓝牙发送给开发板;开发板使用现有 Whisper-Tiny 识别文本,再调用指定的官方 Qwen3-0.6B 生成回答,将识别文本和回答显示在板端终端并返回手机.

首版建议采用 **Android App + Wi-Fi + 按住录音、松开发送 + 单轮问答**.Android 是当前规划假设,手机系统在开发前确认.Wi-Fi 先完成闭环;蓝牙保留独立传输接口,需要蓝牙时再接入,不将两种链路同时可用作为首版前提.如果现场必须使用蓝牙,在资源核实阶段调整优先级.

本 Demo 的 C++ 要求是本次明确指定的应用范围例外.现有 `models/` 模型部署仍遵守仓库 Python 规范,不改共享 skill,不将现有 Whisper Python 入口改回 C++,也不以启动 Python 进程代替本 Demo 的原生 C++ 推理接入.

首版处理完整短音频,不做实时流式 ASR、TTS、连续唤醒、多用户并行、多轮历史或实际设备控制.文本输出指 Whisper 转录和 Qwen 回答,不自动执行回答中的命令.

## 平台与业务隔离

依赖方向固定为:

```text
手机 App ── 音频/事件协议 ── 传输适配器
                                  │
                                  ▼
                           VoiceSession 业务编排
                                  │
                    仅依赖 IAsrEngine / ILlmEngine
                                  ▲
                                  │ 实现接口
                     MTK Whisper / Qwen 适配器
                                  │
                          官方 SDK 和模型运行包
```

| 层 | 职责 | 依赖约束 |
| --- | --- | --- |
| `core/` | 音频和文本类型、会话状态、调用顺序、错误及事件定义 | 使用标准 C++,不包含 SDK、Socket、BlueZ、Android、系统路径和动态库类型 |
| `../platforms/mtk/` | MTK 模型加载、张量绑定、NPU 调用与 Qwen 官方运行接口对接 | 通用 Runtime 只维护一份,模型引擎按需链接;SDK 类型保持内部可见 |
| `../platforms/linux/` | WebSocket 网络收发、可选蓝牙收发、操作系统相关设施 | 协议转为统一请求与事件;不决定 ASR/LLM 的调用顺序 |
| `adapters/ros2/` | 转录、回答、请求状态及后续任务反馈对接 | 仅转换输入输出,不实现 ASR/LLM 业务,不向核心传播 ROS 类型 |
| `main.cpp` | 读取配置、通过选定平台工厂创建服务、注入依赖并启动 | 平台绑定集中在公共平台目录及构建配置,不在业务代码散布 `#ifdef MTK` |
| `mobile/` | Android 录音、连接、上传和文本展示 | 仅了解传输协议,不依赖板端 SDK、模型文件布局或 NPU 细节 |

最小接口职责如下,实际签名在开发时按官方 API 能力确定:

- `IAsrEngine`: 输入规范化音频和语言选项,返回转录文本及停止原因.
- `ILlmEngine`: 输入用户文本和生成限制,输出文本增量及最终停止原因.
- 传输接口: 接收开始、音频块、结束和取消请求,返回统一事件;Wi-Fi 与蓝牙复用业务流程.

通过 CMake 独立 target 约束依赖: `voice_core` 不链接 MTK、网络库或 ROS 2;公共平台后端与本模块 ROS 2 target 实现核心接口;最终可执行程序负责组装.纯数学且后端无关的预后处理可保留在本模块,原生张量尺度、布局及 SDK 绑定属于平台后端.公共依赖由顶层按构建范围查找,不在本目录复制 SDK 查找规则.未来更换芯片时替换引擎实现和平台配置,不修改会话状态机.

## 手机通信与交互设计

### Wi-Fi 首版

建议采用一个 WebSocket 会话同时上传二进制音频和返回 JSON 事件,便于显示识别文本及增量回答.开发前核实板端可用网络库并选择最小依赖,不将具体网络库暴露给业务层.

手机与开发板连接同一网络,App 手动配置服务地址.首版不增加自动发现、热点配网或公网接入.配对凭据和服务地址来自本地配置,不写入公开示例.

音频协议固定为 **16 kHz、单声道、PCM S16LE**.App 明确转换为约定格式再发送,不直接传 AAC/AMR 等压缩录音.按下开始录音,松开发送结束标记;单次最长 30 秒.板端收齐后再执行 ASR,不把分块传输称为流式识别.超过时长直接报错,不沿用模型脚本的静默截断行为.

最小协议约定:

| 方向 | 消息 | 必要内容 |
| --- | --- | --- |
| 手机 → 板端 | `start` | 协议版本、`request_id`、采样率、声道数、采样格式、识别语言 |
| 手机 → 板端 | 二进制音频帧 | 请求归属、连续序号和 PCM 数据;具体帧头在实现前固定 |
| 手机 → 板端 | `end` / `cancel` | 请求编号;结束时附总字节数,便于完整性检查 |
| 板端 → 手机 | `status` | 请求编号和接收、识别、生成阶段 |
| 板端 → 手机 | `asr_result` | 完整转录文本 |
| 板端 → 手机 | `text_delta` | 顺序递增的回答文本片段 |
| 板端 → 手机 | `done` / `error` | 停止原因或稳定错误码、可读说明 |

采用有界缓冲与单活动请求,繁忙时明确拒绝新任务.检查音频偶数字节、序号、总长度、30 秒上限和上传超时;断线后不复用未完成音频.每个请求最多产生一个终态事件.取消后停止后续生成并丢弃迟到结果;SDK 无法中断的当前调用在安全边界结束,不承诺即时中断 NPU.

App 页面保持简单: 连接状态、录音按钮、识别文本、回答文本和错误提示.板端同步显示关键阶段与回答增量;UTF-8 字节未完整时暂存,避免中文乱码.

### 蓝牙扩展

若首版选择 Wi-Fi,蓝牙作为后续独立适配器.BLE GATT 或 Bluetooth Classic 的选择取决于手机系统、板端硬件、系统服务和官方可用接口,本轮不预设均受支持.

蓝牙实现必须定义分包长度、序号、重组、流控、超时及断连处理,并复用相同的请求/事件语义.BLE 上传整段 PCM 的实际吞吐需经板端实测,不能按 Wi-Fi 的传输速度承诺体验;若速度不满足要求,先报告限制再调整方案.

## 模型接入要点

### Whisper

1. 复用既有双 DLA、`runtime_contract.json`、Mel 滤波器和分词/解码参数.先核对部署包实际内容,不从文件名猜测契约.
2. C++ 对齐现有 30 秒补齐、400 点 Hann 窗、160 点帧移、80 维 Log-Mel 等处理及数值边界,保留量化、反量化和存储补齐规则.
3. 按契约处理 Encoder → Decoder 特征及各 KV Cache 的尺度转换,不将 INT16 内存当作 FP16,也不直接跨图复制不同尺度的数据.
4. 保留 256 槽滑动 Cache、448 位置、提示 Token、禁止 Token、EOT 与生成上限规则.中文和英文分别采用已核实的语言提示,不照搬当前英文评价配置.
5. 接入与现有资源一致的 C++ tokenizer/解码实现;现有 Python tokenizer 不能直接视作 C++ 可用资源.缺少依赖时先确认来源和许可证.
6. 空音频、无有效语音或空转录不触发 Qwen.静音/无语音检测策略需单独核实,不把任意非空转录都视作有效输入.

### Qwen3-0.6B

1. 核对指定 NAS 官方包的文件清单、版本、许可、AArch64 库、运行配置与示例.优先直接调用官方原生 API,不修改模型配方.
2. tokenizer、chat template、特殊 Token、上下文上限、停止条件和思考模式以该包为准.现有 `Qwen3NoInput` 仅是核查线索,不能据此直接确定最终聊天模板.
3. Whisper 转录作为用户消息传入,固定系统提示仅限定简短中文或用户语言回答.首版每轮重置聊天状态,避免请求间串话;检查完整模板编码后的长度,超限明确返回错误.
4. 如官方接口支持增量回调,直接转换为 `text_delta`;若仅支持整段结果,如实提供整段输出,待 API 能力确认后再确定首版流式验收要求.
5. 记录 EOS、生成上限、取消和失败等停止原因.不删除或伪造原始输出以掩盖模板不匹配问题.
6. 两个模型按 ASR → LLM 顺序调用,先评估能否同时常驻内存;若不足,在适配层按阶段释放/加载,说明启动及切换开销,不修改业务调用接口.
