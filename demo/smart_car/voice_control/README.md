# Whisper + Qwen3-0.6B 语音输入、文本输出 Demo

本文件是语音 Demo 的整体计划与当前进度入口,模型适配、环境准备、板端验证和应用联调均在此更新.更新时间: 2026-11-04.

当前状态: **官方 SDK 部署 + MTK 评价协议已确认;模型配置已同步服务器并成功生成三步 QLG 与 S100 工作配置.已获依赖下载与候选环境构建授权,当前先完成用户要求的通用 skill 整理.尚未量化、编译、板端推理或完成 USB 语音闭环.**

## 当前执行范围

先完成 S100 / nash-e 上 Qwen3-0.6B 模型适配,再实现本目录的 USB 麦克风语音多轮对话.使用 Python 实现推理编排、前后处理、评价与统计,直接调用官方 Python 接口或 SDK 动态库,不维护自有 C++ 推理程序.

量化顺序已确认: **先做 W4,确认效果明显不满足需求后再换 W8.** 先排除模板、Token、KV Cache 和执行实现错误,不因少量不理想回答直接改 W8.区分原始权重精度、W4 量化网格、编译后权重存储与实际计算类型;若 S100 SDK 把 W4 参数映射为 INT8,如实记录,不称为原生 INT4 执行.激活及公开 I/O 类型另行审计,不凭 W4 或 embedding FP16 名称宣称 W4A16.

最新决策: **部署优先采用现有 S100 官方 SDK 的 Qwen3 网络适配和量化规则,关键评价指标与现有 MTK LLM 保持一致.** 直接从指定 original 原始权重开始,不另写网络或将量化强改为 MTK W4A16.官方 Qwen3 W4 示例的前置 QLG 默认为 W4A8,采用 QuaRot → OmniQuant LWC → GPTQ;小模型按 SDK 要求保留 LWC 量化阈值优化,随后按 nash-e 静态规则校准和编译.示例型号为 1.7B,0.6B 的实际加载、量化及编译仍待验证.模型来源、量化规则与评价协议分别记录,不以 SDK 自带评价默认值替代本仓库协议.

首版链路:

```text
USB 麦克风 → ALSA → 16 kHz 单声道 PCM → Silero VAD
    → Whisper 转录 → 空文本/异常重复/无效文本检查
    → 历史消息 + Qwen3-0.6B → 终端流式回答 → 更新会话
```

首版支持连续监听、自动分句、中文输入验证和至少三轮对话;输出转录与回答文本.不加入 TTS、唤醒词、语音打断、手机 App、蓝牙、ROS 2 或真实底盘控制.原 MTK 手机录音方案保留为后续扩展,不作为本轮交付前提.

## 阶段二: Qwen3-0.6B W4 适配

模型代码放在 `rdk_models/gen_ai/llm/qwen3_0_6b/`,风格参考现有 MTK LLM,复用 RDK 本地配置、上传和评价工具.模型代码、正式资源与日期临时数据分离,不将大模型放入 Git.

- `deploy/compile.sh`: 顺序执行转换、量化、编译、部署、同协议子集精度与少量数值对比,保存 summary_test.json 和文本示例.

- 初始目标为 Prefill 分块 256、上下文 2048、关闭 thinking;最终以 S100 编译与 Runtime 验证为准.输入和输出共享上下文预算,超限明确提示,不截题或丢样本.
- 保留官方 tokenizer、chat template、BOS/EOS 和停止规则.校准使用训练划分,评价使用独立测试划分.
- 先单轮,再三轮及以上历史对话.展示输入、实际模板、Prefill 提示和 UTF-8 完整字符流式输出,记录停止原因及生成 Token 数.

完成条件: 真实 S100 模型加载和生成成功,位宽与执行位置审计完成,示例可复现.编译成功与推理成功分别记录.

## 阶段三: 小范围精度、耗时与 W4 决策

本轮已授权编译、少量数据精度及性能验证,不启动完整基准或业务微调训练;官方配方中的量化阈值优化属于量化步骤.优先使用已有离线数据.用户已另行明确授权匹配 SDK 的 Torch/CUDA 等依赖缺项下载,仍按固定版本和候选环境流程执行.

| 项目 | 本轮安排 | 对比与边界 |
| --- | --- | --- |
| WikiText2 | 固定 16 个 128 Token 测试块 | 每块重置上下文,计分后 127 个 Token,按总 NLL/有效 Token 数计算 PPL;报告浮点 PPL、BPU PPL、绝对差及相对增幅 |
| MMLU | 固定 100 题,0-shot,seed=17 | 沿用现有抽样、提示词和选项延续评分协议;记录正确数、Accuracy、精度下降百分点和与浮点预测一致率;不自动套聊天模板 |
| 数值误差 | 最多 5 次输入的首个 Prefill | 同一输入、有效位置与对应 logits 比较 CosSim/RMSE/NRMSE;NRMSE=100*RMSE/RMS(reference),不比较不同模型的 logits |
| 对话功能 | 中英文、约束输出及至少三轮历史 | 检查乱码、重复、提前停止、上下文记忆,不将样例当完整精度 |
| 性能 | 128 个输入 Token、最多生成 128 Token;独立预热 | 与 MTK 定长基准对齐,记录实际生成数、停止原因、TTFT、Prefill/Decode token/s 和端到端耗时;提前 EOS 如实记录,不称完整 128 Token 测速;测速关闭流式打印 |
| 内存 | 实际 Python 推理进程高水位 | 记录峰值 RSS 及采集范围,不等同全部 BPU/驱动内存 |
| 部署体积 | 实际模型包 | 记录编译 HBM、外置 embedding 等必要辅助权重、原始权重及部署总大小,不只统计单个 HBM |

浮点与板端必须使用同版本权重和协议.若 SDK 提供可用的软件量化参考,加入该层对照,区分量化误差和板端错误.缺少可测分项时留空并说明,不借用厂商、主机或其他平台成绩.

沿用 MTK 的指标和协议,不沿用历史分数或跨模型做精度差值.Qwen3 使用自身的原始权重浮点参考;记录参考参数及计算 dtype、设备与有效样本覆盖.若 SDK 默认使用 2048 Token PPL 窗口或不同评分方式,其结果仅作 SDK 诊断,与本仓库 128 Token 协议分开.Prefill 分块可以采用官方 256,性能输入仍为 128 个真实 Token,记录补齐后的执行长度.纯 BPU、Python 同步调用及端到端计时分别说明,不能将不同边界的速度直接对比.

W4 出现明显退化时,先检查浮点是否同样答错,再排查模板、Token、KV、校准和执行实现.确认量化引入明显 PPL/任务精度损失或对话退化后再改 W8,用同一批数据复测并解释选择依据.不预设未经用户认可的损失阈值,不以修复代码错误为由直接切换精度.最终保留选定配方和必要对比结论,不堆积历史产物.

### 双报告约定

- `results/summary_test.json`: compile 固定子集的任务精度、浮点损失、少量数值误差及缺失项.
- `results/summary.json`: evaluate 独立评价的精度、性能、RSS、实际范围和缺失项.本轮按用户要求先评价少量数据,明确写 subset,不冒充正式全量.
- 两份报告互不覆盖.未来正式评价采用 skill 的固定 1000 题 MMLU、57 学科、seed=17 与完整 WikiText2 test,不在本轮默认执行.
- 模型指标保存在模型 results,本文记录阶段结论并链接实际报告,不维护另一套指标副本.失败现场和中间结果放日期临时目录.

## 阶段四: USB 麦克风语音 Demo

Qwen 模型完成后再实施本阶段,只建立当前功能需要的文件,不预建多层空框架.

1. ALSA 持续采集,选择稳定设备标识,转换为 16 kHz 单声道 PCM.检查采样能力、音频长度和设备错误,不将采集分块称为流式 ASR.
2. 优先用 Silero VAD ONNX CPU 模型检测语音起止,配置前置音频、最短语音、结束静音和最长语句.资源固定版本并记录具体来源,运行时不自动下载.
3. 复用现有 S100 Whisper Python 前后处理和模型接口,补充中文语言提示.原英语测试不证明中文可用;保持 256 Cache、448 位置及现有解码协议的正确性.
4. 对无语音、空转录及异常重复做明确过滤;中文正常短句不得因过严检查误丢弃.检查结果给出可读提示.
5. 将有效转录作为用户消息与历史一起传给 Qwen,优先保持模型加载.至少验证三轮,支持清空会话;超限按完整轮次裁剪,保留系统提示并预留输出预算.
6. 采集与推理通过有界队列解耦,明确忙碌时的排队或丢弃策略并提示,避免无限积压.Whisper 与 Qwen 顺序执行,核对同时常驻的内存可行性.
7. 终端显示监听、分句、识别、生成和结束状态,实时刷新回答;正常退出释放设备和模型资源.无需额外后台守护或自动重启机制.

配置模板只放公开参数,真实模型路径与设备选择使用本地配置.核心音频处理和会话代码不散布平台地址,后续扩展复用同一逻辑.
