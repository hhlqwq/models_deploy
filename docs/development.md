# 开发规范

先确定本次工作涉及的模型、目标或 Demo，说明打算改哪些入口，代码修改按已确认的方案进行。修改前检查工作区状态，分批提交时按主题核对暂存差异，提交信息使用中文并标注 `docs`、`feat`、`fix` 等前缀。

## 模型适配

1. 从现有平台目录定位同类模型，核对源代码、权重、版本、许可及输入输出。可参考 [模型模板](../templates/model/)，实际目录按现有平台入口和任务范围确定。
2. 模型 README 写明支持的目标、依赖、资源布局、当前入口和已知限制。通用张量契约放在模型文档，目标特定布局、量化参数、前后处理差异写在对应实现或配置旁。
3. 优先复用已有的独立步骤和公共工具。涉及量化、编译、上传或评价时，先确认入口的组合行为。运行结果链接到模型目录中的实际文件或说明。

## Demo 开发

应用按场景建目录。README 说明场景、平台、依赖模型、配置、输入输出和构建运行命令。流程图画出输入、应用步骤、后端、输出，以及有限输入或持续运行的结束条件。规划中的模块注明设计状态。

平台层管理 Runtime、设备和系统差异。业务逻辑可先用文件或录制数据开发；需要外设时单独记录设备型号、权限、接入方式和实际运行情况。模型交互所需的张量、tokenizer、坐标、单位及时间戳按实际接口说明。

## 公共代码与配置

- 新代码采用 Google 风格、4 空格缩进。函数包含中文注释或文档字符串并使用英文符号。耗时循环显示进度或关键阶段。
- 先复用已有公共逻辑。抽取模块时同时核对 Shell 调用、Python 导入、容器入口和独立板端包。
- 公开配置提交示例或默认值，真实路径、连接信息和凭据留在本地。大模型、数据集、SDK 和中间产物按 [环境说明](environment.md) 存放。
- 精度、性能和内存按实验目的选择。比较结果写清同一版本、后端、输入、评分协议和范围。静态检查、构建、目标端运行、评价和外设联调分别记录。

## 文档维护

构建和运行命令随代码维护在对应 README。平台共性和跨模块约定放在 `docs/`。修订时更新受影响的链接；已完成的工作链接到实际记录，后续想做的事项放到路线图。模型适配细节见 [model-deploy](../.agents/skills/model-deploy/SKILL.md)。
