# 新增运行目标

先确定要在什么设备、系统和后端上运行哪个模型或 Demo。一个新目标可以只推进到配置、导出或编译阶段，之后按需要继续跑目标端或应用。

## 接入步骤

1. **识别目标。** 选稳定的 `target_id`，记录设备型号、SoC、系统和 CPU 架构、加速后端、编译目标、SDK 与运行库。未知项标为待核实。公开字段在 `configs/platforms/` 维护，实际连接和资源路径留在本地覆盖文件。
2. **选择可复用范围。** 核对现有工具链镜像、运行接口、模型格式和固件兼容范围。先共享已确认一致的模型来源、预后处理或参考数据，再决定是否共享编译和 Runtime 代码。
3. **只接一条明确的路径。** 选择一个代表模型，先接必要的导出、目标转换和加载步骤。需要容器时按 [platform-docker](../../.agents/skills/platform-docker/SKILL.md) 准备。PC CPU 等目标可使用已有标准模型直接推理，流程由实际后端决定。
4. **隔离运行产物。** 按目标设置模型包、板端工作目录、临时结果和回传路径。模型包携带与目标匹配的辅助文件和配置。需要对比时，保存对应的输入、协议和参考结果。
5. **按需接入 Demo。** 在应用配置选择对应的模型包。优先使用固定文件确认业务输入输出，按场景再接实际外设。记录已验证的范围和当前限制。

## 已有入口的扩展位置

| 目标 | 处理方式 |
| --- | --- |
| RDK S100P | 增加独立目标配置。在确认 S 系列工具链版本后复用适用的主机步骤，使用 S100P 的编译目标重新生成制品并记录其 Runtime。 |
| RDK X5、X3 | 各自确定转换器、编译目标、格式和板端 API。复用模型身份和可比的参考，给目标专用步骤单独落位。 |
| MTK Genio Pro 5100 | 现有 [`genio_5100.yaml`](../../configs/platforms/genio_5100.yaml) 是占位。核实实际设备和 SDK 后，参数化现有默认 G720 的配置、目标选择与运行路径，再做最小模型试点。 |
| 其他地平线板卡、瑞芯微、高通 | 按实际 SoC 和系统定义目标。先核对能否复用现有后端，若工具链、格式或 API 不同则增加独立适配。 |
| NVIDIA、Intel 和通用 PC | 区分嵌入式设备与桌面主机、系统与处理器架构、CPU 参考和加速后端。将目标与选择的运行后端写入结果记录。 |

RDK 当前的配置解析和回传路径含 S100 默认值，MTK 的配置与存储解析含 G720 或 `mtk_models/` 假设。新增配置时要同时检查这些消费者。拆分和迁移顺序见 [项目架构](../architecture.md)。
