# 开发路线图

路线图记录可选方向。具体顺序按设备、工具链和当前实验需求决定。已完成或暂停的工作见 [开发进度](progress.md)。

## 仓库结构演进

| 阶段 | 工作范围 | 判断依据 |
| --- | --- | --- |
| 模型目标试点 | 选已有两套实现的 Whisper tiny，先对照 G720 与 S100 的模型来源、输入输出和编译部署路径。统一可共享的模型身份，目标独立存放。 | 旧命令到新位置的映射清楚。板端包、NAS 和回传路径能区分目标。报告可追溯到原始模型与平台。 |
| 索引收敛 | 根据试点选目录发现或轻量索引。检查 `registry/models.yaml` 与 `tools/check_registry.py` 的依赖，优先清理重复的状态、字段和来源记录。 | 模型能按身份和目标查找，文档引用、检查入口和现有结果索引一致。 |
| 工具分层 | 先归类主机转换、目标端运行、共享评价、资源管理和 Demo 专用工具，按已有调用逐批移动。 | Shell、Python、Docker、板端包和回传调用可逐批复核。 |

目录与边界见 [项目架构](architecture.md)。

## 候选运行目标

| 方向 | 起点 |
| --- | --- |
| RDK S100P | 核对现有 S 系列工具链和实机 Runtime，选择一个已有 S100 模型做目标专用编译实验。 |
| RDK X5、X3 | 分别核对板卡、对应算法工具链和板端 API，从一个小视觉模型开始。 |
| MTK Genio Pro 5100 | 从已有占位配置出发，核实实际设备和 SDK，再选择代表模型。 |
| 其他地平线板卡、瑞芯微、高通 | 有明确设备和用途后整理平台配置与兼容信息。 |
| NVIDIA、Intel、通用 PC | 按设备、OS 和运行后端选目标。有需要时先用 PC 参考运行帮助定位问题。 |

接入步骤见 [新增运行目标](guides/add-platform.md)。历史候选模型记录在 [原始候选清单](../registry/target_models.yaml)，其中选型供后续参考。

## 应用方向

优先整理独立 Demo 的输入输出和可复现例子。语音可按需验证 FILE 与真实 MIC，视觉可从固定 RGB 输入、米制深度、栅格和路径可视化开始。两个子应用的接口明确后，再考虑 ROS 2 小车集成。
